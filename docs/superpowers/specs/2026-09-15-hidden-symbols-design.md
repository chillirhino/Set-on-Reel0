# Скрытые символы (hidden) и свободные id

Дата: 2026-09-15

Две связанные фичи в контуре сетов: новый тип символа `hidden`, который перед
стопом выбирает по весам, во что превратится, и правка id символов вручную.

Контур с импортом `.py`-игры (`gameio`, `mathexact`, `feasibility`, `generate`)
эта работа не трогает: там нет символов-сетов и точный RTP считается по другому
пути. Всё изменения живут в `sets.py`, `play.py`, `service.py` и `web/`.

## Словарь

**hidden** — символ, который никогда не доходит до подсчёта линий. Перед стопом
он превращается в другой символ, выбранный по собственным весам.

**Бросок** — одно обращение к генератору случайных чисел, выбирающее цель для
одного hidden-id в одном спине.

**Цель** — символ, в который hidden превращается. Целью может быть любой символ,
кроме hidden-ов.

## Правила механики

Порядок событий в спине: **бросок → замена → стоп → игра по линиям**.

1. Ровно один бросок на каждый hidden-**id**, присутствующий в сете.
2. Все экземпляры этого id на экране превращаются в один и тот же символ.
3. Два разных hidden-а бросают независимо, каждый из своего распределения.
4. Замена происходит до всего остального, поэтому подсчёт линий, триггеров
   бонуса и фриспинов, антисипейшна и разнообразия символов видит уже
   превращённое поле. Hidden, ставший бонусным символом, честно добирает порог.
5. Состояния «остался hidden-ом» нет — hidden превращается всегда.

**Целью может быть любой символ, кроме hidden-ов** — включая wild и special.
Не хочешь, чтобы hidden давал wild, — ставь wild-у вес 0. Запрет на hidden как
цель убирает цепочки превращений и невозможность зациклиться.

**Веса относительные.** Пользователь вводит произвольные числа (10, 30, 5),
инструмент сам считает и показывает проценты. Ноль и пустое поле означают «в
этот символ не превращается».

## Хранение

### Тип

`sets.TYPES` получает шестой элемент:

```python
TYPES = ("low", "middle", "high", "special", "wild", "hidden")
```

Отсюда бесплатно приезжает `type:hidden` в правилах пересечения: `strips.py`
работает с типами обобщённо через `_matches` и `_is_filler`, его править не
нужно.

### Веса в set.json

У символа появляется поле `weights`. В расчёте оно читается только у типа
`hidden`, но у символа, которому тип сняли, таблица не стирается: иначе смена
типа туда-обратно молча уносила бы заполненные веса.

```json
{
  "id": 20,
  "type": "hidden",
  "name": "mystery",
  "image": "sym_20.png",
  "pays": {},
  "weights": { "3": 10, "5": 30, "9": 5 }
}
```

Ключ — id символа-цели строкой, значение — относительный вес (число > 0).

### Нормализация весов

Веса чинятся при каждом чтении документа, как всё остальное в `_normalize`.
Отбрасываются:

- нечисловые значения;
- нули и отрицательные числа;
- ссылка символа на самого себя;
- ссылки на id, которых в сете нет (например, цель удалили);
- ссылки на символы типа `hidden`.

Последние две проверки требуют знания всех символов, поэтому делаются
отдельным проходом в `_normalize` после того, как список символов собран, а не
внутри `_fit_symbol`.

### Выплаты hidden-а

Hidden вычёркивается из платёжной таблицы целиком: `sets._pay_table` пропускает
символы типа `hidden`. Это делает «hidden не платит за себя» свойством
конструкции, а не договорённостью — даже если бы hidden каким-то образом
уцелел на поле до подсчёта, платить ему было бы не по чему. Побочно это убирает
пустые строки hidden-ов из таблицы `symbol_hits`.

## Свободные id

### Что меняется

`_renumber` уходит вместе с её вызовом из `_write` и с починкой нумерации в
`state()` (блок «съехавшую нумерацию чиним на месте»). Её помощники —
`_move_image` (двухфазное переименование картинки) и `_remap_target` (правка
цели `id:N` в правиле пересечения) — остаются и переиспользуются: вместо
перекладки всех id разом получается перекладка одного.

- Допустимый id: **1..999**. Верхняя граница совпадает с уже существующим
  ограничением на ссылку символа в триггерах (`_clamp(..., 0, 999, 0)`).
- `next_id` остаётся `max(id) + 1` — дыры не заполняются.
- Символы сортируются по id и в файле, и в интерфейсе. Hidden-ы 20 и 30 просто
  оказываются в конце списка.

### Смена id

Новая операция `sets.set_id(old_id, new_id)`:

1. Проверка диапазона: 1..999, иначе внятная ошибка.
2. Занятый id — **обмен номерами**. Отказ здесь был бы отказом от самой
   возможности переставлять: в сете, пронумерованном подряд, занято всё, и
   «сделай этот символ пятым» не сработало бы никогда — только переезд за
   пределы существующего диапазона. Обмен ничего не теряет, оба символа увозят
   с собой картинки, стеки, правила и ленты, а интерфейс говорит вслух, что
   номерами обменялись двое, — молча второй символ не переезжает.
3. Перенос всех ссылок идёт **одним проходом по отображению** старых id в новые,
   а не двумя переименованиями подряд: при обмене 3 и 7 после первой половины
   оба символа оказались бы на одном номере.
4. Перенос затрагивает:
   - файл картинки → `sym_<new_id>.<ext>` (двухфазное переименование через
     `_PENDING`/`_flush_images`, чтобы не затереть чужой файл на полпути);
   - ключи в `reels[*]` — стеки символа на каждом риле;
   - цели `id:N` в `gaps` (обе стороны правила);
   - значения в уже сгенерированных `strips`;
   - `triggers.bonus.symbol` и `triggers.fs.symbol`;
   - ключи `weights` у всех hidden-ов и id самого hidden-а, если переименовывают
     его.

### Попутное исправление

Сегодня `_renumber` переносит id везде, кроме ссылок на символ в триггерах, —
то есть автоперенумерация уже молча ломает настроенные бонус и фриспины. С
ручной правкой id это станет частым случаем, поэтому перенос ссылок в триггерах
добавляется в общий механизм.

### Совместимость

Существующие сеты имеют id 1..N подряд. Отключение автоперенумерации на них не
меняет ничего: перенумеровывать нечего. Файлы сетов остаются байт в байт теми
же до первой ручной правки.

## Игра и расчёт

### Модуль play.py

Разрешение hidden-ов — отдельная функция, а не вкрапление в цикл:

```python
def hidden_ids(types) -> frozenset[int]
def roll_hidden(weights, rng) -> dict[int, int]
```

`roll_hidden` возвращает отображение «hidden-id → выбранная цель», по одному
броску на id, в детерминированном порядке (по возрастанию id), чтобы один и тот
же сид давал один и тот же результат.

### Отсутствие регрессии по случайности

Бросок выполняется, **только если в сете есть hidden-символы**. Это не
оптимизация, а требование совместимости: лишнее обращение к `random` сдвинуло бы
всю последующую последовательность, и сет без hidden-ов при том же сиде дал бы
другую симуляцию, чем сегодня.

### Замена в горячем цикле

`simulate` предвычисляет по каждой позиции каждого барабана кортеж
`(cells, set(cells), bonus_count, fs_count)`. К нему добавляется флаг «в этом
окне есть hidden». В цикле спина:

- окно без hidden-ов идёт прежним путём, без единого лишнего действия;
- окно с hidden-ами пересобирается по отображению броска, и для него заново
  считаются счётчики бонуса и фриспинов и маска «эта клетка была hidden-ом».

Цикл остаётся один, с дешёвой проверкой флага, — дублировать шестьдесят строк
ради микровыигрыша не стоит. Страховкой от регрессии служит эталонный тест
(см. ниже), а не разделение кода.

### Маркер на линии

У выигрыша уже есть признак `with_wild` — «вайлд попал в оплаченную часть
линии». Рядом появляется `with_hidden` по тому же правилу: hidden засчитан,
только если превращённая клетка попала в оплаченные `length` барабанов, а не
просто оказалась где-то правее.

### Проверка перед запуском

Если hidden-символ лежит в сгенерированной ленте, а весов у него нет или все
нули — спин и симуляция падают с `SymbolError` вида «у символа 20 не задано ни
одного веса превращения». Hidden, который заведён, но ни на один рил не
поставлен, ошибкой не считается.

## Статистика

### Один спин

`one_spin` возвращает поле уже превращённым, плюс два новых куска:

- `hidden_map` — что во что превратилось в этом спине;
- маска по клеткам окна: какая клетка пришла из hidden-а и из какого именно.

Интерфейс рисует в клетке выпавший символ (wild, low, любой) с пометкой-уголком
«был hidden» и подписью, из какого hidden-а он пришёл. У линии, собранной с
участием hidden, в списке выигрышей стоит тот же маркер.

### Симуляция

**Таблица `symbol_hits`.** Строка сегодня выглядит как
`[id, длина, раз, выплата, раз с wild, выплата с wild]`. В конец добавляются
`раз с hidden, выплата с hidden`. Колонки приписываются справа — существующие
индексы не сдвигаются, разбор в `web/app.js` не ломается.

**Новый блок «Разрешение скрытых».** По строке на hidden-символ: сколько раз
крутился и во что превращался — счёт и фактический процент по каждой цели рядом
с заданным весом в процентах. Расхождение факта с весом на большом числе
раундов сразу покажет ошибку в реализации; в интерфейсе расхождение больше двух
процентных пунктов подсвечивается.

Отдельно считается, в скольких спинах символ вообще попал на экран. Бросок
делается каждый спин, а на поле hidden оказывается не всегда, и эти две цифры
путать нельзя: первая проверяет распределение, вторая — частоту механики.

**Общая цифра.** Рядом с уже существующей `wild_win` появляется `hidden_win` —
сколько выплачено по линиям, в оплаченной части которых участвовал hidden.

## Интерфейс

### Вкладка «Скрытые»

Новая вкладка сразу после «Символов» — hidden это свойство символа, логично
держать рядом.

Содержимое: карточка на каждый hidden-символ. В шапке картинка, id и имя. Внутри
строка на каждый возможный символ-цель (все символы сета, кроме hidden-ов): имя,
картинка, поле веса, рядом посчитанный процент. Снизу сумма весов.

Пустое состояние: если hidden-ов в сете нет, вкладка объясняет, что тип ставится
на вкладке «Символы».

### Вкладка «Символы»

- в переключателе типов появляется `hidden`;
- id становится редактируемым полем; выходящий за 1..999 id даёт сообщение об
  ошибке и поле возвращается к прежнему значению, занятый — обмен с сообщением
  «символы 1 и 5 обменялись номерами»;
- у hidden-символа вместо таблицы выплат стоит пояснение «за себя не платит» со
  ссылкой на вкладку «Скрытые». Показывать поля, которые ни на что не влияют, —
  приглашение заполнить их и потом искать, почему выплата не сработала.

### Вкладка «Статистика»

- окно спина рисует маркеры превращённых клеток;
- таблица попаданий получает две колонки справа;
- под таблицей появляется блок «Разрешение hidden», скрытый, если hidden-ов нет.

## Обмен с сервером

Новые операции в `service.py`, по образцу уже существующих:

| Операция | Что делает |
|---|---|
| `symbols_weight` | вес превращения: hidden-id, цель, число (пусто/0 — убрать) |
| `symbols_id` | сменить id символа |

Обе возвращают целиком свежее состояние сета через `_do`, как и остальные
операции над символами.

Экспорт и импорт сета файлом менять не нужно: они гоняют документ целиком, и
`weights` уезжает вместе с ним.

## Тесты

**Эталон против регрессии.** До правки снимается прогон симуляции на
существующем сете с фиксированным сидом; числа записываются в тест константами.
После правки тот же сид обязан дать те же числа. Это прямая проверка обещания
«не сломать то, что уже работает».

**Новые проверки:**

- один бросок на id: три экземпляра hidden-а на экране дают три одинаковых
  символа;
- независимость: два hidden-а на поле тянут из разных распределений и могут дать
  разные цели;
- распределение: на большом числе бросков доли целей сходятся к весам;
- замена до триггеров: hidden, превратившийся в бонусный символ, добирает порог;
- hidden не платит за себя и не появляется в таблице попаданий;
- пустые веса у выложенного на рил hidden-а дают `SymbolError` до запуска;
- смена id переносит картинку, стеки, правила пересечения, ленты, ссылки в
  триггерах и ссылки в весах hidden-ов;
- занятый id меняет символы местами: обе картинки, обе раскладки на рилах и обе
  доли ленты расходятся по новым номерам, а повторный обмен возвращает всё как
  было;
- id вне 1..999 даёт ошибку и не меняет документ;
- нормализация выбрасывает вес на несуществующий символ, на себя и на другой
  hidden;
- сет без hidden-ов при том же сиде даёт прежнюю последовательность спинов.

## Что сознательно не делается

- **Точный RTP с hidden-ами.** Контур `mathexact.py` относится к импорту
  `.py`-игры и с сетами не пересекается. Hidden считается симуляцией.
- **Цепочки превращений.** Hidden не может стать другим hidden-ом.
- **Веса по рилам.** Бросок один на спин, поэтому веса по определению общие для
  всех барабанов. Разные веса на разных рилах — это другая механика («бросок на
  рил»), она не заказана.
- **Шанс остаться hidden-ом.** Превращение всегда происходит.

# Дополнение от 2026-09-16: распределения по экрану

К симуляции добавлены три распределения, считаемые по видимому полю.

**Роялсов на экране.** Роялсы это тип `low`, картинки — все остальные. Считается
одно распределение: они дополняют друг друга до полного экрана, поэтому картинки
это остаток, и второе распределение было бы его зеркалом. В подписи стоит и
среднее по картинкам, и их доля экрана.

**Вайлдов на спин** — сколько вайлдов лежит на поле. В подписи доля спинов без
единого вайлда.

**Рилов с вайлдом** — на скольких барабанах лежит хотя бы один. Отличается от
предыдущего тем, что два вайлда на одном риле это один рил: для механик, которые
смотрят на барабаны целиком, важно именно это.

## Считаем после превращения

Все три меряются по экрану **после подстановки скрытых**. На стопе hidden уже
стал другим символом, поэтому клетка из него идёт в ту группу, в какую попал её
символ: скрытый, ставший вайлдом, считается вайлдом, ставший роялсом — роялсом.
Иначе цифры описывали бы поле, которого игрок не видит.

Технически это означает, что при подстановке пересчитываются **все** счётчики
позиции, а не только триггерные: и роялсы, и вайлды.

## Совместимость

Новые счётчики не обращаются к генератору случайных чисел, поэтому эталонный
прогон не сдвинулся ни на одну цифру.

Проверки: каждый спин попадает ровно в один столбец каждого распределения; сумма
роялсов и картинок равна экрану; число рилов с вайлдом не больше числа вайлдов;
столбец «ноль вайлдов» совпадает со столбцом «ноль рилов»; доля роялсов на
экране сходится с их долей в лентах; скрытый, ставший вайлдом, попадает в
вайлды, а ставший роялсом — в роялсы.


## Длина комбинации: частота и деньги в одной карточке

Сначала это были два блока: узкая гистограмма «Длина выигрышной комбинации» и
широкая «RTP по длине». Они отвечают на две половины одного вопроса, и чтобы
увидеть главное — что тройки берут 81% попаданий, но только 41% денег, —
приходилось сличать их глазами.

Слиты в одну карточку «Выигрышные комбинации по длине». На строку длины —
**две шкалы рядом**: «как часто выпадает» и «сколько платит», между ними счёт и
доля попаданий, справа доля выплат и вклад в RTP в процентных пунктах.

Первая версия слияния оставила одну полосу — по деньгам, — а частоту свела к
тексту. Это была ошибка: вопрос карточки именно в расхождении между частотой и
деньгами, а его видно только когда обе полосы стоят рядом и их длины можно
сравнить напрямую. У ×4 частота 16% от максимума, а деньги 81% — текстом это не
читается.

Проверка на связность остаётся прежней: сумма процентных пунктов по длинам равна
общему RTP.
